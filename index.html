A microphone array measures the time difference between mics, and that difference is the bearing. Overlay that on a camera and a hissing valve, a leaking gasket or an arcing relay becomes a bright spot you can put your finger on. This page computes the real array response — including the failure mode that ruins most first builds.

What this is actually computing

For a linear array of N mics spaced d apart, steered to angle φ while the source sits at θ, the normalised response is |Σ e^{j·k·d·n·(sinθ − sinφ)}| / N, with k = 2πf/c. Delay-and-sum. The beam points at θ by construction; everything interesting is in what else it points at.

Drag spacing past c/2f and watch the ghost lobes appear — the array starts hearing sounds that are not there. This is the single most common reason a DIY array "works" in testing and fails in a plant room.

Scope, honestly

This is a simulation of the array response, not a recording. It models the physics exactly, which is what you need before buying mics. It does not model reverberation, microphone mismatch, near-field curvature or self-noise — all of which degrade a real array, which is why tools/beamform.py ships alongside: it runs the same delay-and-sum on a real multi-channel WAV, so the code path exists the day the hardware does.
